# Продуктовая концепция RentalDesk

**Обновлено:** 30.10.2026. **Статус:** основная цель ПРИНЯТА; отдельные модули ЗАПЛАНИРОВАНЫ.

## Зачем это делаем

RentalDesk — система управления арендой/прокатом оборудования (первый предметный фокус: строительные инструменты) с поэкземплярным учётом и дальнейшей аналитикой жизненного цикла.

**Главная мотивация проекта:** глубокая инженерная практика PHP/Symfony backend с полноценным циклом коммерческой разработки. **Не** утверждается, что найден уникальный продукт, проверена рыночная ниша или гарантирована коммерческая окупаемость. Внешняя коммерциализация возможна, но пока вторична.

Критерий ценности обучения: разработчик способен **самостоятельно** пройти путь «требования → проектирование → код → тестирование → нагрузка → отказ/диагностика → деплой», понимая, почему система работает.

## Основные сценарии продукта

1. Менеджер видит каталог оборудования и наличие.
2. Менеджер регистрирует конкретные физические экземпляры оборудования, их состояние и стоимость приобретения.
3. Сотрудник оформляет заказ и бронирует оборудование на временной интервал, не допуская двойной выдачи.
4. Система сопровождает выдачу, возврат, повреждения и обслуживание каждого экземпляра.
5. Владелец анализирует фактическую доходность, себестоимость обслуживания и загрузку парка.

## Направления развития (пока гипотезы/этапы, НЕ готовые функции)

| Модуль | Что решает | Инженерные темы |
|---|---|---|
| **Smart Availability** | Доступность конкретных экземпляров на даты, бронирование и конкуренция | интервалы, SQL, блокировки, транзакции, идемпотентность |
| **DamageProof** | Фото состояния при выдаче/возврате, история доказательств | файлы, объектное хранилище, аудит, безопасность |
| **Maintenance Brain** | Ремонты, износ, расходы, жизненный цикл экземпляра | state machine, доменная модель, события |
| **Rental Intelligence** | Маржинальность, окупаемость, простой, загрузка | финансовая точность, отчётный SQL, агрегирование |
| **Purchase Advisor** | Подсказки о целесообразности покупки/списания | метрики, аналитические алгоритмы, прозрачность рекомендаций |
| **Payments** | Оплата, возвраты, сверка статусов и сбои интеграций | FakeGateway, sandbox, webhook, идемпотентность, retry |

Технические темы для дальнейших этапов: Symfony Messenger, RabbitMQ **по необходимости**, CI/CD, наблюдаемость, RBAC, аудит, тестирование отказов. Не добавлять брокер, Kubernetes, микросервисы или другую инфраструктуру лишь ради резюме.

## Продуктовые принципы

- Реальные бизнес-операции важнее красивого каталога без логики.
- Операции с деньгами и арендой должны быть воспроизводимыми и проверяемыми.
- Нельзя терять историю из-за изменения карточки оборудования или тарифов.
- UI развивается вместе с API: каждая законченная серверная фича получает понятный пользовательский сценарий.
- Чёрно-оранжевая тема **Graphite & Ember** сохраняется; качество UX, доступность и работающие сценарии важнее декоративных эффектов.
- Финансовые цифры, графики и рекомендации не выдумывать: отображать только данные, для которых существует реальный источник.

## Не входит в ближайшую цель

- Доказать рыночную уникальность.
- Делать микросервисную архитектуру ради сложности.
- Подключать реальные платёжные системы до готовности базовых процессов заказа/резервирования.
- Писать фронтенд руками разработчика backend: он сфокусирован на PHP, Vue берёт на себя ассистент с обязательным тестированием интеграции.
