# Краткий контекст для нового диалога / ассистента

Это не новый проект. Сначала используй как источник истины `docs/README.md`, `PRODUCT_VISION.md`, `ARCHITECTURE.md`, `ENGINEERING_PROCESS.md`, `CURRENT_STATE.md`, `API_CONTRACTS.md`, `ROADMAP.md` и ADR в текущем Git-репозитории. Если документ устарел относительно кода, проверь фактическое состояние, не угадывай.

**RentalDesk** — учебно-инженерный продукт управления прокатом строительного оборудования; целью является самостоятельная практика разработчика PHP/Symfony на уровне зрелых коммерческих задач. Коммерческая уникальность не доказана, не является обязательным условием. Перспективные фичи: Smart Availability, DamageProof, Maintenance Brain, Rental Intelligence, Purchase Advisor, платежи.

**Текущий стек:** Symfony 7.4, PHP 8.5, Doctrine ORM/DBAL, PostgreSQL/Docker, WSL; отдельно Vue 3/TS/Vite, графитово-чёрный/оранжевый UI. Архитектура: модульный монолит REST. Пользователь **сам пишет backend**, ассистент помогает постановкой, теорией и ревью и **сам создаёт frontend**, проверяет API-интеграцию.

**Что сделано:** `InventoryItem` с DB CHECK, GET/POST `/api/inventory`, UI каталога и создания оборудования (пользователь подтвердил). **Что не сделано:** завершённая Asset-модель, заказы в Symfony, бронирования, платежи. Файлы `Asset`, `OrderItem`, `RentalOrder` уже созданы как заготовки, не считать их завершёнными.

**Инженерный принцип:** требования + инварианты + архитектурные trade-offs → Git-ветка → самостоятельная реализация PHP → code review → миграции/значимые тесты/HTTP-проверки → frontend → фиксация в Git. Без ненужных фреймворков, механических микроупражнений и технологического карго-культа.

**Критический риск:** текущая схема `InventoryItem.stock/reserved`; хотим учёт `Asset` как физического экземпляра, но стратегия устранения двух источников истины и backfill пока **не решена**. До изменения БД нужен ADR.

**Ближайший шаг:** завершить первый baseline-коммит Git без секретов и незавершённых сущностей, затем ревью существующего `Asset.php` в ветке `feature/asset-model`.
