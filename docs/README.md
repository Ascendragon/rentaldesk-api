# RentalDesk — инженерная документация

**Статус:** живой документ, отправная точка для всех следующих задач. **Срез:** 30.10.2026.  
**Источник истины:** файлы в Git-репозитории, а не ответы ИИ, память чата или архивы отдельных версий фронтенда.

## Маркеры статуса

- **ПРИНЯТО**: согласованный принцип / решение, менять через ADR.
- **РЕАЛИЗОВАНО**: код написан и соответствующее поведение подтверждено проверкой.
- **ЗАПЛАНИРОВАНО**: целевая возможность, но ещё не выполнена.
- **ОТКРЫТО**: вопрос требует проектирования или проверки.
- **РИСК**: потенциальная проблема, которую нельзя замалчивать.

Важно: **план разработки не равен принятому архитектурному решению**, а наличие PHP-файла не равно завершённому тикету.

## Правило обновления

1. Перед новой сложной фичей прочесть соответствующие документы и ADR.
2. Если архитектура меняется, создать/обновить ADR, зафиксировать основания и последствия.
3. После каждого завершённого тикета обновить `CURRENT_STATE.md`, `API_CONTRACTS.md` и при необходимости `ROADMAP.md`.
4. Изменение документации входит в тот же Git-коммит/PR, что и код, либо в отдельный осмысленный `docs:`-коммит.
5. При конфликте актуального кода с документом проверить ситуацию и исправить документацию или код, а не утверждать, что всё работает.
6. Не хранить секреты, реальные пароли и токены в документации.

## Репозитории

На момент этого среза backend и frontend находятся в разных локальных папках WSL:

```text
~/Projects/rentaldesk-api/       # Symfony + PostgreSQL
~/Projects/rentaldesk-frontend/  # Vue + Vite
```

**ПРИНЯТО:** отдельные Git-репозитории для существующих проектов на текущем этапе. Документация в этом архиве предназначена для `rentaldesk-api/docs/`. Общие контрактные изменения должны учитываться и во фронтенде.
