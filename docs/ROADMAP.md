## Инженерные условия

- Новое API считается готовым только после проверки HTTP и согласования frontend-контракта.
- Не смешивать учёт `stock/reserved` и агрегирование `Asset` до согласованной стратегии перехода.
- Не добавлять незавершённые заказные Entity в миграции Asset.
- Значимые этапы завершаются ревью, осмысленными Git-коммитами и актуализацией `docs/`.


## Актуальное следующее действие (30.10.2026)

- Прогнать весь PHPUnit, проверить test DB и зафиксировать `RENTAL-CORE-001` в `feature/api-problem-details` (либо согласованной ветке Git).
- Установить frontend v0.4.2, подтвердить сборку и реальную работу `422`/`409`.
- Реализовать `GET /api/inventory/{id}/assets` (RENTAL-005.6) и подключить реестр к реальным данным PostgreSQL.
- Стратегию `stock/reserved` и Asset согласовать отдельно до миграции.
